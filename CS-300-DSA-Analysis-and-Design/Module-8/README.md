## 🧠 Final Reflection

### **What was the problem you were solving in the projects for this course?**  
The main problem in CS 300 was designing and implementing a course advising program capable of loading course data, searching for individual courses, and printing a full course list in alphanumeric order. I explored three different data structures—vector, hash table, and binary search tree—to determine which one best supported efficient searching and sorted output. Ultimately, the binary search tree provided the best balance of performance and structure for the final implementation.

### **How did you approach the problem? Why are data structures important to understand?**  
I approached the problem by breaking it into phases: pseudocode design, data structure analysis, and final implementation. Understanding data structures is essential because each one offers different performance characteristics. Choosing the right structure can dramatically improve efficiency, especially as datasets grow. This course reinforced how algorithmic complexity directly impacts user experience and system scalability.

### **How did you overcome roadblocks during the activities and project?**  
Most roadblocks came from debugging pointer logic, recursive functions, and edge cases—especially in the BST removal function. I overcame these challenges by stepping through the logic carefully, drawing diagrams, and testing with multiple inputs. When something didn’t behave as expected, I isolated the function, added print statements, and validated each step until the issue became clear.

### **How has your work on this project expanded your approach to designing software?**  
This project strengthened my understanding of planning before coding. Writing pseudocode for three different data structures forced me to think about structure, flow, and efficiency before touching C++. It also showed me how important it is to evaluate trade‑offs early in the design process. I now approach software design with a stronger emphasis on choosing the right tools and validating assumptions before implementation.

### **How has your work on this project evolved the way you write maintainable, readable, and adaptable programs?**  
Working through multiple implementations taught me the value of modular functions, clear naming conventions, and consistent commenting. I also learned how important it is to separate logic into manageable components—loading data, searching, printing, and traversal—so the program remains easy to update or extend. These habits will help me write cleaner, more maintainable code in future courses and professional projects.
