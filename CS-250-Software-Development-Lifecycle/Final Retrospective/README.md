Final Sprint Review & Retrospective

This repository contains my Sprint Review and Retrospective for the SNHU Travel application, completed as part of the CS‑250 Software Development Lifecycle course. 

The project served as a pilot for transitioning ChadaTech from a traditional waterfall model to an Agile Scrum framework. 

Throughout the course, I rotated through the roles of Product Owner, Developer, Tester, and Scrum Master, producing artifacts aligned with each phase of the SDLC.

This README summarizes the purpose of the paper, key themes, and what the retrospective demonstrates about Agile practice and Scrum adoption.

📌 Project Overview

The SNHU Travel project simulated the development of a travel‑planning application using the Scrum framework. The goal was to explore how Agile practices improve adaptability, communication, and iterative value delivery compared to waterfall methods.
The final retrospective paper reflects on:
- How each Scrum role contributed to the project
- How user stories evolved and were completed
- How the team handled interruptions and shifting priorities
- How communication supported collaboration
- Which Scrum events and tools were most effective
- Whether Scrum was the right methodology for this project

🧩 Key Insights From the Retrospective

Scrum Roles in Practice
Rotating through all four roles provided a full view of how Scrum teams collaborate.
- As Product Owner, I translated customer needs into actionable user stories with clear acceptance criteria.
- As Developer, I identified dependencies and communicated blockers early.
- As Tester, I validated increments against acceptance criteria and provided iterative feedback.
- As Scrum Master, I facilitated communication, removed impediments, and reinforced Agile values such as transparency and psychological safety.

User Story Completion

User stories evolved through refinement, discussion, and clarification.
For example, the destination search story expanded to include filtering by destination type and preferred activities, demonstrating how iterative refinement improves clarity and reduces rework.

Handling Interruptions

Scrum’s adaptability was a major strength.
When priorities shifted—such as new stakeholder insights—the Product Owner reprioritized the backlog, and the team adjusted in the next sprint without derailing progress.

Communication & Collaboration

Effective communication artifacts included:
- A Developer email requesting clarification on feature requirements
- Facilitation of the Vision Quest Software discussion, emphasizing consensus and psychological safety
These examples highlight how structured communication accelerates progress and reduces ambiguity.
Scrum Events & Tools
The retrospective evaluates how each Scrum event contributed to success:
- Product Backlog ensured transparency
- Sprint Planning aligned the team on goals
- Daily Scrums surfaced blockers early
- Sprint Reviews enabled stakeholder feedback
- Retrospectives supported continuous improvement

Evaluating Scrum for This Project

Scrum proved highly effective for the SNHU Travel project due to:
- Evolving requirements
- Frequent feedback
- Need for rapid iteration
- Focus on user value

Challenges included role‑switching and managing dependencies, but the benefits outweighed the drawbacks.
